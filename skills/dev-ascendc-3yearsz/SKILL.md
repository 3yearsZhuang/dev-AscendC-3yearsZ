# dev-AscendC-3yearsZ

作为总控，保留用户目标、任务约束、版本选择和提交协调；把执行任务交给对应子技能，按真实产物复核结论。先读 [委托与交接协议](references/delegation.md)，再只加载当前需要的角色。技能清单见 [suite.json](suite.json)。

## 按任务委托

| 当前需要 | 执行技能 | 主要交付 |
|---|---|---|
| 新题、接口或评分未明确；需要实现/实验方案 | [Plan](../dev-ascendc-plan-3yearsz/SKILL.md) | 题目契约、环境事实、方案与可检验假设 |
| 新实现、编译修复、数值修复 | [Implement](../dev-ascendc-implement-3yearsz/SKILL.md) | 指定范围内的源码、最终 SHA、相称检查 |
| 独立审查、用例设计、精度/访存/同步诊断 | [Review](../dev-ascendc-review-3yearsz/SKILL.md) | 分层检查、反例和绑定源码的审查结论 |
| 已有算子性能优化或失败消融 | [Tune](../dev-ascendc-tune-3yearsz/SKILL.md) | 瓶颈假设、隔离候选、对照/复测建议 |
| 题目下载、冻结、授权提交、查询/恢复 | [Judge](../dev-ascendc-judge-3yearsz/SKILL.md) | 精确 payload、回执、原始结果与在途状态 |

新题通常是 Plan→Implement→Review→Judge；持续优化通常是 Tune→Review→Judge，Tune 可把较大实现工作转给 Implement。用户仅要求查询、审查、解释或单点修补时只运行相关阶段，不强制全链，也不预载所有开发知识。一个角色完成后，总控决定下一步，子技能不递归派发完整工作流。

## 调度与状态

- 发给子 agent 的消息包含：用户目标与约束、角色 SKILL.md 的绝对路径、精确输入版本、独占写入范围、验收范围、产物路径和已存在的授权。技能被引用不自动扩大权限。
- 有独立工作可并行时使用当前环境的子 agent 工具；只读数值/语义审查与资源/依赖审查可并行，不同候选分配不同目录。共享源码只允许一个写入者。
- 缺少子 agent 工具时，在同一 agent 中按角色读取并执行，报告实际执行方式。职责分离仍然有效；不要伪称已做独立评审或并行执行。
- 简单任务合并执行，复杂数值、归约、布局、跨核依赖才扩大审查。既有产物仍适用时从相应阶段恢复，不因新会话重跑全部流程。
- 项目状态记录任务 ID、角色、输入/输出 SHA、产物和在途请求，是索引；源码、执行日志和官方回执是事实依据。上游产物变化时使依赖它的旧审查失效，只重做受影响部分。

## 接收与决策

真实委托使用协议中的任务/结果文件，接收后运行 [check_handoff.py](scripts/check_handoff.py)。它核对声明、当前文件 SHA、产物和写入范围；不认证日志真实性、平台授权或 NPU 正确性。简单的同 agent 阶段切换可以等价简记，仍需核对版本与验证范围。

`FAIL`/`CONCERN` 也是有价值的完成产物。结构一致的失败可用于下一轮诊断或已授权探索，不能机械地把交接检查的非零退出码变成全赛事禁令。源码/身份不一致的结果不能用于当前版本晋升；被跳过或未运行的检查不能被汇总成通过。

题目分随全站最优耗时漂移，候选是否提高以榜单行是否改选该候选为准；可见点耗时合计与总分可能方向不同。
保留三类指针：本地主版、实验候选、官网选定提交。探索依据剩余时间/配额与信息价值；晋升依据用户目标、正式评分和覆盖。允许部分得分的比赛可以选择官方更高分的 WA/RE，明确失败覆盖并保留完整正确性回退版；不擅自推导隐藏计分公式。

## 总控始终负责的边界

- 用户本次技术来源、题面/参考比较器、真实 Host/stream 与只读模板优先。核函数题保留 `run_kernel`；传统 ACLNN 和 PyTorch extension 只在真实契约要求时使用。详见 [任务契约](references/contest-contract.md)。
- 单账号只安排一个 Judge 提交协调者。只有已有用户授权覆盖题目、候选与操作时才能 POST；查询、prepare、审查或收到候选不自动授权。已明确授权的工作不重复询问。
- POST 受理不明时保留未知状态并恢复；已有 ID 只 GET 同一请求。同源码历史结果不单独证明原请求身份，不能据此重投。
- 区分静态检查、CPU 模型、目标编译、NPU 执行、官方评测；可见 5/5 不等于全 15 点已验证。失败零耗时不作速度证据，单次收益不表述成稳定加速。
- 晋升前重新核对最终源码、实际发送内容、结果 ID 和覆盖，更新 verified-result；默认不去注释、不把旧 SHA 的验证转移到新源码。

交付所选源码、实际验证层次、官方分/排名快照、未解决问题及全部在途请求。经验按 [证据准入](references/evidence-learning.md) 更新；完整轮次记录留项目，技能只吸收会改变决策的窄结论。
