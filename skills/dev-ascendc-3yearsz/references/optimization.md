# 算子实验、优化与诊断

修改算法、Tile、精度路径、搬运或同步时读取。官方提交工程约定见 [CANNJudge 工作流](cannjudge-workflow.md)，当前赛事与执行环境见 [任务契约](contest-contract.md)；此文件不固定赛区、设备、教程来源或计分公式。

## 目标侧硬约束与已验证陷阱

- UB 内的向量与搬运操作数按 32 B 对齐。对 `LocalTensor` 取 `t[i]` 这类小偏移（使字节偏移不是 32 的倍数）作为向量指令目标，会在核启动阶段直接失败：可见点全部 `time=0`、`precision_ratio=0`、顶层 Runtime Error。需要在缓冲区里做变长追加时，让每次追加落点都在对齐边界（FP32 追加 8 的倍数），非对齐尾段先写出再重置起点，而不是把数据留在缓冲区中间。
- 工程常为 C++14，`if (sizeof(T) == 4) { ... } else { ... }` 不是 `if constexpr`，两个分支都会为每种 dtype 实例化。把 `LocalTensor<float>` 与 `GlobalTensor<T>` 混在同一调用会得到 `deduced conflicting types for parameter 'T'`（对 half/bf16 也会编译 FP32 分支）。统一先落到 `LocalTensor<T>`，再用对三种类型都可编译的 `Cast` / `ReinterpretCast` 转 FP32。
- `DataCopy` 的连续快路径只在行距与长度满足 32 B 对齐时可用，其余情况保留 `DataCopyPad`；两种路径各自被哪些输入走到要写进检查记录。
- 一个文件里同时保留多条算法路径时，为每条路径写清判据（dtype、M/N 阈值、核数下限）；只在小规模成立的路径不要在大规模静默接管。
- `time=0` 且所有可见点一致的 Runtime Error 属于启动级失败（资源请求、非法偏移、非法指令），不是数据相关错误；只有逐点耗时不同的失败才需要按输入域分析。

## 元素级流式算子的核数与分块

- “每核一块、核数拉满”通常不是最优：核数过多时每核只剩一个 Tile，DMA 延迟与建拆开销暴露。实测中把约 8 K–65 K 元素的规模固定到 20–24 核、更大规模按 `ceil(N/16384)` 放核，比 `ceil(N/2048)` 的版本把该题官网分从 54.68 提到 57.31；这是该题当时的证据，不是通用核数公式。
- 让一个输入块服务多行输出可以成倍减少 GM 读取，但三角形/步进布局的输出在 GM 上不连续，回写要按行分段；分块越大可用核数越少，必须给“块数小于核数”的小规模保留原路径。
- 先量化再重构：纯写输出的下界、只读输入的下界、去掉某段算术的差值，比继续微调 Tile 更能决定要不要改数据复用结构。

## 先确定这次实验回答什么

- 从当前题面、实际 `reference.py`、Host 入口和平台反馈确定 dtype、参数域、输出分配、容差、kernel 启动及 ACL 约束。只使用用户本次允许的技术来源；历史任务的唯一教程限制不自动延续。
- 保留可回退的完整正确性基线，分别标识本地主版、实验候选与官网选定提交。三者可以不同，每份结果绑定自己的源码 SHA。
- 实验记录写明：基线与候选、改变的路径、待验证假设、预计收益或诊断信息、已完成检查、设备上仍未知的行为。独立改变优先分别评测；接口、布局互相依赖时可以一起改，但需说明可区分哪些原因。
- 小步首评用与修改相称的样例、数值边界、分发/尾部、类型和资源检查。高风险重构增加相应验证，不为每次 Tile 微调重复庞大矩阵。CPU 测试数量不能换算成设备成功概率。
- 探索性评测与晋升主版分开决策。按当前用户目标和实际评分规则安排配额；部分通过但官方分更高的候选可在允许时晋升，并明确失败覆盖。无需给所有赛事套用“全通过才值得实验”。

## 数值与参考语义

- 优化顺序、分组、累加类型、转换位置或近似公式时，按实际比较器验证。更接近实数答案不一定更符合参考的浮点递推。
- 若参考要求 FP16 逐步舍入，`[2048, 1, 1]` 可区分逐步 half 累加与 FP32 累加后转换；FP32 的 `[2**24, 1, -2**24]` 可区分顺序累加与高精度/重组。先确认参考的 dtype 行为再使用这些反例，不把某个 NumPy 环境的行为推广到全部题目。
- 计数器也是数值算法的一部分。参考 FP32 逐次加一在 `2**24` 附近可能饱和；整数计数后转 float 不一定等价。检查计数起点、最大可达长度、整数溢出及 Host 的长度截断。
- 改变分组会改变未命中 lane 经历的运算。用 `v=a` 模拟不更新，后续若计算 `v-a`，仍可能产生 `Inf-Inf -> NaN`；审查 inactive 元素的保存/恢复，不能只验证活动 source 顺序。
- NaN、Inf、正负零和 payload 是否属于等价要求，由题目输入域与比较器决定。记录验证范围；不要为让候选通过而悄悄改变比较器。
- 数学近似需覆盖误差极值、分段接缝、定义域端点和实际 dtype。精度合格只支持正确性判断，新增串行乘加、转换或屏障仍可能使设备变慢。

## 搬运、资源与依赖

- 写出 GM→UB→计算→GM，以及 Scalar/Vector/MTE 的生产者与最后消费者。队列按 Alloc、写入、EnQue、DeQue、消费、Free 管理；复用 scratch 前确认所有旧消费者已结束。
- 按每次 `InitBuffer` 的真实 buffer 数、对齐槽位、scratch、同步区累计 UB。例如三个双槽队列各含 `Tile` 个 T，声明量为 `6*Tile*sizeof(T)`，不能按三个槽计算。保留编译器临时量未知的边界。
- 192 KiB 可以是自定实验预算，不能冒充硬件上限。调整预算需说明依据；资源合规只意味着候选可尝试，不证明更大 Tile 更快。
- 分开检查 GM 有效长度、UB 容量、指令粒度。UB 分配 32 B 不表示 FP32 标量输出拥有 32 B GM；精确 4 B 输出不能因 UB 对齐而写回 8 个 float。核实当前目标的精确长度搬运接口。
- 核尾、Tile 尾、短行和归约 padding 分开测试。凡会读到的 padding 都需要有效初值；不因 CPU 分配了额外保护空间就认定设备访问合法。
- API 的元素数、字节数、block/repeat stride 与 mask 字序分别核对。外层参数为 `uint32_t count` 不证明内部 repeat 无上限，也不证明短尾会被自动处理。按目标 CANN/架构的实际重载建立模型。
- mask 变化后恢复所需模式。用独立单 bit/lane 边界探针验证公开接口语义，避免模型与候选同时写反 mask 字序而“互相通过”。
- PIPE_ALL、局部屏障、事件和队列解决不同依赖。屏障减少必须说明被保留的依赖；增加全屏障也不保证性能或消除跨核问题。
- 单核完成读取不代表其他核也读完。跨核复用 workspace，或借用输出区存 partial 时，需证明所有消费者完成后才开始覆盖，并核对调度、参与核数、标记初始化和可见性。
- 记录 workspace 字节、额外 kernel 数、ACL 调用、同步与释放成本。平台若约束每 round 释放或累计 ACL 次数，需按真实 profile 计算；不能把跨轮缓存当成无代价兜底。

## 模型与目标编译的边界

- CPU driver 保留影响 C++ 语义的 Host 宏和类型；简化 `GM_ADDR` 等定义可能掩盖目标声明错误。翻译 kernel 启动时以一个 compound 语句替换，避免改变无花括号 `if` 的控制范围。
- 核对变量类型传播、signed/unsigned 到浮点的转换与目标 Bisheng 诊断。CPU clang 可编译只能说明模型工具链接受，不能推出 AICore 编译器支持。
- 模型应检查真实分配的 GM/UB 范围、队列生命周期、实际分发和启动次数。`GetPhyAddr()` 后的裸指针可能绕过 wrapper 检查；需要时以精确分配配合 ASan/UBSan 补充。
- helper 穷举、种子化大计数器或省略长前缀可验证局部性质，但不能登记成完整 kernel 回归。模型自己的插桩错误、准备失败和候选错误分开记录。
- CPU 同步执行、线程屏障或 sanitizer 不证明目标指令、异步事件、缓存一致性和性能。模型修正后保留旧反例，使旧错误确实失败，再重测受影响候选。

## 让失败减少未知

| 反馈 | 下一步应区分的原因 |
|---|---|
| Compile Error | 真实目标日志中的宏、声明、API 重载、dtype 与标量转换；用最小接口变化检验。 |
| Wrong Answer | 数值递推、尾部、mask、别名、inactive lane、异步依赖；保留独立反例和旧模型盲区。 |
| Runtime Error | 实际资源请求、kernel/ACL 契约、范围与生命周期；错误码与资源配置相关不等于已定位唯一根因。 |
| `cpu_timeout` / TLE | Host 建表、重复扫描、workspace、算法路径、同步等候选原因；缺少执行阶段时用合法消融区分，不能直接断言死锁或标量吞吐。 |
| 结果缺失或查询失败 | 进入提交恢复流程，先确认受理状态；不作为算子失败或新一次评测。 |

同一失败反复出现且新改动没有增加区分能力时，换假设或停止该方向；不把单次失败写成永久禁令。平台拒绝的诊断方式改成本地诊断或合法算法消融，不靠变形绕过提交检查。

## 非 Pass 提交也能读到的读数

平台在非 Pass 提交上仍返回每个可见点的 `time` 与 `precision_ratio`（`best` 模式不会用它替换已选最佳）。因此可以提交“保留完整搬运骨架、故意算错”的探针来分离成本：只写下界的版本、只读下界的版本、去掉一段算术的版本。

- 探针是诊断，不是验证：隐藏点永不返回耗时，探针不能晋升、不能用来恢复隐藏 shape，仍然消耗配额；源码、SHA、用途和读数与正式候选分开保存。
- 先看地板再动结构：若最大公开点的纯写下界是 8.19 µs 而当前实现是 33.85 µs，问题在输入复用或算术；若地板已接近当前值，则先改搬运结构没有意义。

## 用正式结果选择实现

- 比较正式覆盖、各点贡献、官方评分及官网选择；失败点的零耗时不进入速度比较。合计耗时只是一项诊断指标，可能与实际积分变化方向不同。
- 保存所有复测值。小幅或混合收益用合理对照确认，不挑最低一次；大幅收益也标明测量次数和适用范围。
- 同一源码的运行间波动不可忽略：两个近乎逐字节相同的 pdist 候选在同一公开点分别测得 39.35 µs 与 25.32 µs。单点单次差值不作为结论，优先看官网是否改选与多轮复测。
- 没有公开 shape 时，点号只能作为结果标识。消融可支持某分支的相关性判断，不能直接恢复精确隐藏 shape，更不能按点号硬编码输出。
- 晋升时绑定最终发送字节与完整终态，并更新主版元数据；未采用候选保留假设和结论，以免重复消耗配额。可复用知识的写法见 [经验准入](evidence-learning.md)。
