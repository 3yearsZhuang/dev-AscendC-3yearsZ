# 分层验证与独立审查

设计测试或复核子技能“通过”结论时读取。适用层次由任务和环境决定，不把每一层都变成小改动的前置手续。

| 层次 | 能证明什么 | 不能据此证明 |
|---|---|---|
| 黑盒用例设计 | 按题面、dtype/属性域、边界和比较器形成测试集合 | 用例已执行或算子正确 |
| 白盒用例设计/审查 | 分发、核/Tile尾部、索引、缓冲存活和同步路径被分析 | 所有设备路径正确或隐藏点通过 |
| CPU 模型/局部探针 | 所建模的数值、布局、边界和接口性质 | 目标编译、异步事件或设备性能 |
| 目标编译 | 指定源码、目标/CANN/编译参数被工具链接受 | 实际执行正确 |
| 本地 NPU 执行 | 实际运行用例的正确性/性能；无 golden 时只能说明冒烟情况 | 未运行用例或官方得分 |
| 官方评测 | 指定 payload/ID 的可见状态、分数与回执 | 未公开用例的具体参数或由 5/5 推断 15/15 |

## 用例设计

黑盒从规范独立导出：有效 dtype/属性、最小/最大参数、跨分发阈值、非对齐尾部与题目允许的数值特殊值。白盒从当前源码导出：每条路径的进入条件、真实 GM 范围、核间输出所有权、buffer 生命周期和参考舍入。将生成的 case ID 与理由保存在产物中。

测试规模与改动相称，不固定生成几百个 case。选少量能区分候选与旧错误的反例；性能用例与功能用例可以不同，但都绑定自己的参数和比较器。生成了集合不等于运行了集合。

## 比较器与执行证据

- 按题目原始规则比较。NaN、Inf、符号零及整数精确性要显式处理；不能用 `abs(a-b)>tol` 的 NaN 行为或一律 float 转换让错误默默通过。
- 不为让实现通过而统一提高中间精度、放宽 half 阈值或替换参考递推。允许时可以把更高精度结果作为独立诊断值。
- 执行结果逐 case 保留 ID、状态、输入/测试集版本、比较器、命令/退出码和日志。保留所有复测，不用后一次 PASS 覆盖同 ID 的旧 FAIL；用 run ID 区分复测。
- 源码、模型、用例、比较器和构建物能取得时各记 SHA。无构建物或没有设备就明确缺失，不伪造 provenance。
- 空结果不通过。重复 ID、缺 case、未知状态或只执行一部分，需要明确范围；`skipped/off/not_available` 与 PASS 分开。无 golden 的执行冒烟不表述为精度通过。
- 文本里写“来自某 skill”及日志非空只是弱标记。主控核对关键执行事实；离线一致性工具不认证文件来自真实设备。

## 工程适配

核函数题用下载工程提供的真实 `run_kernel`/main/比较器，不能为了套测试 skill 加上 `TORCH_LIBRARY`、改只读文件或伪造 `op_host/`。传统工程按其 ACLNN 接口测试；PyTorch extension 只在项目本来采用它时使用。TTK、msprof、模拟器均按可用性和任务需要选择；本机不可用时继续有价值的本地检查与合法官方实验，不把工具缺失变成全任务永久阻塞。

独立审查者优先读规范与实际源码，再看作者结论。报告按 PASS/FAIL/CONCERN 给出范围和证据；静态 PASS 与官方选版是不同决定。返回格式见 [委托协议](delegation.md)。
