# 传统注册工程的条件路径

只有当前题目/项目确实要求传统注册算子时读取。核函数题继续保留下载的 `run_kernel` 工程；此路径不用于把它转换成注册工程。

按真实原型建立对应表：输入/输出/属性 → `OpDef` → `InferShape/InferDataType` → Tiling 字段 → kernel 模板/分发 → ACLNN 调用。属性的默认值、输入张量的运行时数据、ValueDepend 与 dtype 支持须对照目标 CANN 版本；不同版本或文档矛盾时保留未确认项。

Tiling 分别回答多核切分、核内 UB Tile、buffer/scratch 存活、尾部与分支覆盖。依据运行平台资源和实际 buffer 槽位计算，不把每核最小字节数、固定 512 元素、8 核或 192 KiB 作为通用常量。每个输入与输出都按本题映射计算 GM 偏移；核尾和 Tile 尾分别覆盖。

使用模板前检查：

- include 后常量、类型和注册宏是否重定义；目标宏/类型是否与工程一致。
- 输入/输出是否均正确偏移，N 不能整除核数时是否漏尾部。
- 对齐以 `sizeof(T)` 和实际 API 单位计算；UB 的 padding 不授权 GM 越界搬运。
- 总 UB 是否含全部队列槽位/scratch；查询了硬件资源不等于实际用于分块。
- 测试是否真的调用所有声称支持的 dtype 路径；失败是否返回非零退出码。
- 张量、workspace、stream 与内存资源的创建/清理是否指向真实分配后的对象。
- 比较器是否正确处理非有限值和大整数；精度规则是否来自题目。

构建、安装与 `aclnn*GetWorkspaceSize`/执行二段式沿用真实工程。安装步骤会改变环境，只在任务已要求且授权的范围执行；本地源码准备与审查无需因此停下。
