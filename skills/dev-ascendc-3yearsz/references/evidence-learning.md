# 从实验中更新技能

一轮实验结束、模型被反例推翻或平台契约发生变化时读取。只提炼会改变下一次决策的知识，完整源码、日志、逐点结果与轮次叙述留在项目证据目录。

## 可复用经验的最小记录

以下是知识记录字段，不替代提交脚本的实验/请求格式。可用 Markdown 小节或项目现有结构保存，字段名可沿用现有工具；未知项写明未知，不补猜测。

| 字段 | 应记录的内容 |
|---|---|
| 来源 `source` | 题面/参考实现、目标 API 文档或源码、CPU 模型、正式设备结果等来源类别；附 URL 或相对证据路径，以及可用的版本、提交 ID、SHA。 |
| 观察 `observation` | 实际读到、运行到或测到什么；包括失败覆盖、错误原文、测量次数。只写证据直接支持的事实。 |
| 假设 `hypothesis` | 对观察的解释、竞争解释，以及什么实验能区分它们。已确认的机制也说明确认依据。 |
| 适用范围 `scope` | 赛事、题目、CANN/编译器/芯片、dtype、参数域、路径或模型限制；通用结论说明为何可泛化。 |
| 日期 `observed_at` | 观察时间与最近核实时间；历史快照不冒充当前平台状态。 |
| 验证 `validation` | 精确源码、模型/测试版本、检查层次、正负控制、正式覆盖及未检查项；区分本地、目标编译和设备结果。 |
| 更新关系 `supersedes` / `superseded_by` | 被更正的旧记录与新证据；旧报告继续保留，显式标记失效或范围缩小。 |
| 决策影响 `decision` | 此经验改变哪一步选择：实验设计、模型、实现条件、恢复规则或晋升依据。没有决策影响时保留在轮次日志即可。 |

## 准入与修订

1. 先冻结事实，再提炼规则。源码、模型或 payload 发生变化时重新绑定；不能把旧完整矩阵的结果重标成最终源码全部通过。
2. 将状态写为待验证假设、本地观察、目标验证或已被更新等清晰类别。一项结果可同时支持局部结论并留下机制未知，不必强行二选一。
3. 反例与最小修复共同支持的窄结论，可以直接指导同环境的下一次工作。跨赛事、芯片或 dtype 扩展适用范围需要额外依据，不要求所有小修复执行同一庞大矩阵。
4. 模型与候选共享错误假设时，旧“通过”不能继续证明该性质。保留能使旧版本失败的独立负控制，记录模型修正影响的报告范围。
5. 性能知识附测量次数、对照和回退点。未采用的性能假设同样有价值；“融合”“双缓冲”“减少 Scalar”都不是实测收益。
6. 通用入口仅保留跨任务仍能改变决策的原则；某场的提交配额、唯一教程、登录方式、禁用诊断、kernel/ACL 限制放入该项目或赛事配置。
7. 新证据推翻旧结论时修订表述和范围，保留原始证据及更新关系。不要把历史失败不断追加成互相矛盾的禁令。

## 常见的错误泛化

| 观察 | 可以复用的结论 | 证据仍不足的说法 |
|---|---|---|
| 本地模型以 192 KiB 拒绝某布局 | 该布局超过本次自定预算，应重新计算槽位、scratch 与目标约束。 | “所有平台 UB 硬件上限就是 192 KiB。” |
| 平台仅返回 `termination=cpu_timeout` | 该版本未在评测时限内完成；下一步需要区分 Host、算法、同步等原因。 | “已经证明某事件死锁”或“已经证明是 Scalar 太慢”。 |
| 改某分支后第 9 点耗时变化 | 在该对照下，第 9 点结果与修改相关；进一步消融可增强分支归因。 | “第 9 点精确 shape 一定是某值。” |
| 扩大 Tile 后报 ACL 错误，减少槽位后通过 | 当前配置影响可执行性，需审查总资源及临时量。 | “这个错误码唯一代表 UB 溢出。” |
| CPU 模型全部通过，设备部分 WA | 当前模型未覆盖某设备/数值性质，需要寻找独立反例。 | “CPU 通过足以证明设备实现正确。” |
| 单次耗时降低不足 1%，官网未选该版 | 记录一次测量与官方选择，视配额决定是否复测。 | “已获得稳定加速并提高赛事得分。” |

## 简短记录示例

```yaml
source: "项目内冻结的旧源码、独立 mask 探针与正式回执"
observation: "旧模型和候选同时把公开 mask 数组的高低字写反；修正模型后旧候选失败。"
hypothesis: "该次 WA 与 mask 字序有关；最小修复和设备结果用于检验。"
scope: "仅所核对的 API、目标架构、dtype 和模式"
observed_at: "实际实验时间"
validation: "填写源码/模型 SHA、lane 正负控制、设备覆盖；未完成的层次明确写未验证"
supersedes: "旧模型相应性质的通过报告"
superseded_by: null
decision: "以后先用独立 lane 探针确认接口语义，再据此验证候选"
```

这是填写结构的示例，不是本技能新运行的设备结果。新任务使用自己的真实时间、路径与证据。
