# dev-AscendC Implement · 3yearsZ

在指定候选目录内交付可复查的实现，以及与该源码绑定的检查结果。用户可单独调用，也可由总控委托。

## 接收任务与写入范围

- 先读 [委托与交接协议](../dev-ascendc-3yearsz/references/delegation.md)，核对输入版本、方案、允许修改范围和独占候选目录。
- 实际读取输入源码并计算 SHA；多文件按协议绑定。若传入 SHA 与文件不符，保留差异并先澄清版本，不能沿用旧结论。
- 只写被分配的路径，默认使用独立候选目录。用户明确指定修改主文件时，先保存冻结输入，再按委托范围修改；不覆盖无关改动或其他候选。
- 独立只读检查可并行；共享文件只允许一个写入者。不自动派整套角色，任务较小时直接完成本阶段。

## 以真实工程为边界

模板或输入语义不清时读 [任务契约](../dev-ascendc-3yearsz/references/contest-contract.md)；打包约定见 [CANNJudge 工作流](../dev-ascendc-3yearsz/references/cannjudge-workflow.md)。

- 根据当前在线 `code_template` 和下载工程决定结构，核实 dtype 的实际编码、Host 类型、宏、签名及 stream。
- `npu_kernel_dev` 保留真实 `run_kernel` 和模板框架，只改允许的文件；不套用 PyTorch 注册、额外主函数或通用 Add 工程。
- 传统工程按实际 Host/Kernel/tiling 模板实现；不能假称它具有与核函数工程相同的自动只读检查。
- 传统工程需要原型、属性、Tiling 与 ACLNN 细节时读 [注册工程条件路径](../dev-ascendc-3yearsz/references/registry-project.md)，先检查模板，不直接复制未经目标验证的教学实现。
- 不修改评测框架、比较器、只读文件或元数据来掩盖不匹配；需要改变范围时返回具体原因。
- 保留输入基线、改动说明及回退路径；候选源码发生变化后，旧 SHA 的测试和官方结果不自动转移。

## 实现与本地检查

改动数值、搬运、UB、尾部或同步时读 [算子优化与诊断](../dev-ascendc-3yearsz/references/optimization.md)。

- 一次候选优先回答一个假设；接口或布局必须联动时，记录耦合原因和可区分的结论。
- 对照参考的累加顺序、dtype、转换位置、舍入及特殊值语义；精度更高不自动等价于参考实现。
- 分别核算 GM 有效范围、UB 所有槽位与 scratch、指令粒度、核尾/Tile 尾和 padding 初始化。
- 写清生产者、消费者、队列与 scratch 生命周期；减少屏障必须保留必要依赖，跨核复用需独立论证。
- 运行与改动风险相称的样例或反例；本地模型保留影响语义的真实类型、宏、分发和精确分配。
- 有可用目标环境时完成约定的目标编译或本地设备检查；缺失环境就记录限制，不用 CPU 通过代替。
- 输出最终候选 SHA 与检查所用源码 SHA；若末次修改未复查，明确该范围未验证。

## 交接

按协议返回实际输入源码 SHA、最终候选源码 SHA、候选和检查产物路径，以及主要改动与待验证假设。

- 列出已做检查、跳过项及原因、未知项和已知在途请求；如无平台操作明确说明，无测试则写未执行。
- 将“本地通过”“目标编译通过”“设备结果”分开陈述；不编造成功、性能、官方覆盖或评分。
- 交给审查或总控进行下一步决策。候选完成不授权 POST、修改官网选择、晋升主版或写入其他角色目录。
