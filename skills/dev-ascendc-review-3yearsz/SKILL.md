# dev-AscendC Review · 3yearsZ

独立核查候选与证据，给出有范围的审查结论。用户可单独调用，也可由总控委托；作者自检不能冒充独立审查。

## 固定审查对象

- 先读 [委托与交接协议](../dev-ascendc-3yearsz/references/delegation.md)，明确审查目标、输入快照和约定的验证范围。
- 实际读取候选，计算精确输入源码 SHA；检查期间保持快照稳定。文件变动则重新绑定，旧报告只属于旧 SHA。
- 只读被审源码；测试、探针和报告写入分配的审查目录。发现修复点先给证据，不直接改实现来使审查通过。
- 可将相互独立的只读检查并行；不自动派一整套角色。若实现与审查由同一 agent 完成，标明是自审，不能借角色名称宣称独立性。

## 黑盒与白盒相互校验

读取实际契约、参考实现、比较器和工程入口；设计测试或核对“通过”范围时读 [分层验证](../dev-ascendc-3yearsz/references/validation-layers.md)，按需使用 [任务契约](../dev-ascendc-3yearsz/references/contest-contract.md) 与 [算子优化与诊断](../dev-ascendc-3yearsz/references/optimization.md)。

- 黑盒从题目语义选择有区分力的输入和边界，避免只复用实现者的同一模型假设；不擅自放宽比较器。
- 白盒核对真实 Host 类型/宏、dtype 分发、入口/stream、可编辑范围、kernel 次数与 workspace/ACL 限制。
- 检查累加顺序、转换和舍入、计数器溢出、inactive lane、NaN/Inf/正负零；范围由输入域与比较器决定。
- 分开检查 GM 精确有效长度、UB 总槽位与 scratch、指令长度/stride/mask、核尾/Tile 尾和 padding 初始化。
- 逐条核对 UB 操作数对齐（向量指令目标的字节偏移为 32 的倍数）与 dtype 分支的实例化条件：C++14 下 `sizeof(T)==4` 的运行时分支同样会为所有 dtype 编译。
- 检查队列生命周期、Scalar/Vector/MTE 依赖、scratch 复用、事件与跨核同步；CPU 同步执行不能证明目标异步安全。
- 本地测试规模与风险相称；必要时用精确分配、sanitizer、独立 lane 探针或负控制查模型盲区。
- 对需要目标编译或设备验证的性质明确检查来源；CPU clang、模拟器或静态推理不能替代缺失的目标证据。
- 把观察、假设、竞争解释和未检查项分开写；某错误码、单点失败或超时不直接证明唯一根因。

## 审查证据本身

- 核对报告绑定的源码、测试/模型版本、命令与结果；旧源码通过、测试准备失败和候选失败分别记录。
- 官方回执检查实际返回 ID、源码绑定、原始状态和可见覆盖；终态不补足隐藏点证据。
- 性能声明检查单位、对照、测量次数和全部样本；失败点零耗时不能变成加速证据。
- 若需核对已有结果记录，可使用共享 [verify_evidence.py](../dev-ascendc-3yearsz/scripts/verify_evidence.py)；一致性通过不证明算法正确。

## 结论与交接

按协议返回实际输入源码 SHA、审查报告和测试产物路径，并给出一个明确结论：

- `PASS`：约定范围的检查已实际完成且通过，关键结论有证据；写清范围，不能扩展成未经验证的设备或全点通过。
- `FAIL`：存在可定位的违约、错误或反例；附精确位置、复现材料、影响范围和最小修复方向。
- `CONCERN`：证据不足、必需检查未执行、关键机制未核实或结果无法绑定；未验证不能报 `PASS`。
- 无论结论为何，都列出已做检查、跳过及原因、未知项和已知在途请求；不编造测试、完成状态或成功率。
- 结论支持总控的实验与晋升判断；本阶段不获得提交权限，也不把审查结果自动变成官方排名结论。
