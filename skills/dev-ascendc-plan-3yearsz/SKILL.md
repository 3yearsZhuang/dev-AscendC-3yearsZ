# dev-AscendC Plan · 3yearsZ

将当前题目的事实整理成可实施、可检验的方案。用户可单独调用，也可由总控按需要委托本阶段。

## 接收任务

- 先读 [委托与交接协议](../dev-ascendc-3yearsz/references/delegation.md)，确认目标、输入、可写产物目录和已知约束。
- 读取实际输入源码并计算 SHA；多文件按协议记录各文件及集合绑定。没有源码时明确写“未提供”，不为规划文档伪造源码 SHA。
- 本阶段通常只写方案和契约产物；不得因收到开发目标就修改主实现、晋升候选或提交平台。
- 独立只读调研可并行；写入遵守独占目录约定。不自动再派完整角色链，工具不可用时按阶段直接执行。

## 核实会改变方案的事实

新题或契约变化时读 [任务契约与计分](../dev-ascendc-3yearsz/references/contest-contract.md)，已有且未变化的记录可复用并注明核实时间。

- 对齐题目 URL/ID、参考实现、比较器、在线模板与本地工程，保存来源路径、版本或 SHA。
- 需要更新平台题面、排名或配额快照时交由 Judge 的只读路径取得，再据这些输入规划；本角色不执行账号平台操作。
- 确认 dtype 编码、shape/参数域、布局、广播、别名、逐步舍入、容差和特殊值要求；未公开输入不从点号猜测。
- 核实芯片、CANN/Bisheng、核数、真实 GM 分配、资源约束与设备可用性；历史赛区和自定 UB 预算不当作硬件事实。
- 根据模板区分 `npu_kernel_dev` 与传统工程，记录真实入口、stream、可编辑/只读文件及 kernel/ACL 限制。
- 核实官方评分、`best`/`last`、可见/完整点数、配额与冷却；不从 ACM/OI 名称推出全通过门槛或计分公式。
- 只在缺失信息会改变当前实现或实验时请求补充；其余未知标记为待核实并继续有依据的规划。

## 形成实现与实验方案

涉及数值、搬运、尾部、资源或同步时，按需读 [算子优化与诊断](../dev-ascendc-3yearsz/references/optimization.md)。

- 明确完整正确性基线、当前候选和官网选定版本各自的身份；不能给变动中的主文件套旧结果。
- 写出算法、Host 分发、GM→UB→计算→GM、资源估算与依赖；说明每个选择依赖哪些已知事实。
- 提出少量有区分力的候选：每个写明瓶颈假设、主要变量、预期观察和推翻条件；有耦合的改动说明原因。
- 将本地语义检查、目标编译和设备实验分层；CPU 模型不能证明异步执行正确或设备加速。
- 按用户目标、实际评分和配额给出实验次序建议；部分得分候选的晋升交总控决定，保留完整正确性回退版。
- 为下一位实现者给出独占候选目录、允许改动范围、需要保持的入口，以及与风险相称的验收要求。

## 交接

按协议返回规划产物路径、实际输入源码 SHA、事实来源和仍待检验的假设，并明确下一阶段可直接执行的范围。

- 列出已做检查、跳过项及原因、未知项和所有已知在途请求；没有执行测试就写未执行。
- 区分“已核实契约”“建议方案”“待设备验证”；规划完成不等于候选正确、编译通过或获得分数。
- 请求越过当前阶段时交还总控或用户；不要为补齐形式上的全流程自行扩大写入或提交权限。
