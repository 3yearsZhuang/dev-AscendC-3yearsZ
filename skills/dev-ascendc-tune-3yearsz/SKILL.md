# dev-AscendC Tune · 3yearsZ

让每轮优化减少一个未知，并用真实结果判断收益。用户可单独调用，也可由总控委托本阶段。

## 接收基线与证据

- 先读 [委托与交接协议](../dev-ascendc-3yearsz/references/delegation.md)，核对目标、可写候选目录、实验预算及允许的本地设备操作。
- 读取基线和候选实际源码并计算 SHA；核对性能结果所属源码、设备、CANN、参数范围、单位和测量次数。
- 区分本地主版、完整正确性回退版与官网选定版本；过期结果不转移给新源码，没有真实性能时先列假设。
- 并行只读分析或互不重叠的候选写入；共享实现只允许一个写入者。不自动派完整角色链。

## 从观察形成可检验假设

按需读 [算子优化与诊断](../dev-ascendc-3yearsz/references/optimization.md)；评分影响实验选择时读 [任务契约](../dev-ascendc-3yearsz/references/contest-contract.md)。

- 从实际逐点耗时、日志与执行路径提出瓶颈解释，区分 Host、算法、搬运、计算、资源和依赖成本。
- 按数据流选择分析层：有通信才分析卡间，有跨核依赖才分析核间，再分析核内；不强迫单卡独立算子补齐无关阶段。理论吞吐/带宽上界用于筛候选，不是实测收益。
- 有目标设备和合适工具时按授权采集 profiling；缺仿真或 msprof 数据可用合法消融继续，不把 `cpu_timeout` 单独判为 Scalar/同步瓶颈，不固定无限诊断预算。
- 每个候选优先改变一个有意义的变量，例如 Tile、分发、精度路径、搬运或同步依赖；耦合改动写清不可分原因。
- 给出预期观察、竞争解释、推翻条件和最小合法消融；超时或错误码单独不足以宣称死锁、UB 溢出或 Scalar 瓶颈。
- 用真实 buffer 槽位、scratch 与对齐核算资源；更大 Tile、融合、双缓冲或更少屏障都只是待检验方案。
- 不用未公开点号恢复精确 shape 或硬编码输出；若诊断方式被平台拒绝，改做合法消融或本地诊断。
- 非 Pass 提交仍会返回可见点耗时，`best` 模式下不替换已选最佳。可用“保留完整搬运骨架、故意算错”的探针测地板（纯写下界、纯读下界、去掉一段算术的差值），据此决定改数据复用还是改算术；探针不晋升、不用于恢复隐藏 shape，与正式候选分开保存。

## 候选与复测

- 只在被分配的候选目录内改动，保留基线和差异；保持当前模板入口、只读范围与数值/同步契约。
- 执行与改动相称的本地语义、尾部、范围和资源检查；测试模型也记录版本，不能与实现共享错误假设而互证。
- 需要目标编译或 NPU 测量却没有环境时明确未知；CPU 时间和模型通过不能作为设备收益证据。
- 已授权的本地设备实验可执行；正式平台评测交唯一 judge 协调者承接，不因调优目标、已有会话或其他子任务授权擅自 POST。
- 保留所有对照与复测值。小幅或混合收益按噪声和配额安排复测，不挑最低值；单次大幅收益也标明次数与范围。
- 判断是否提高以官网是否改选该候选及其分数为准；可见点合计与总分可能方向不同，同源码同一公开点的运行间波动可达数十个百分点。
- 失败点零耗时不纳入速度比较；单位不明保留原值，耗时合计只作诊断，不替代官方分数。
- 同一失败重复出现且新改动无区分力时换假设或停止该方向，将失败产物保留以避免重复消耗。

## 建议与交接

按协议返回实际输入源码 SHA、各候选最终 SHA、候选/实验产物路径、瓶颈假设和证据支持的结论。

- 将观测收益、噪声范围、未解决正确性风险与建议下一步连在一起说明；没有结果就交付实验计划。
- 官方排名、部分得分取舍、探索配额和主版晋升由总控按用户目标与真实计分决定；本阶段只提供有依据的建议。
- 列出已做检查、跳过项及原因、未知项与所有已知在途请求，保留各 submission ID 与对应 SHA。
- 不宣称未运行的实验完成，不把候选源码修改后的状态沿用为旧结果，也不把一次测量写成稳定加速。
- 可复用发现按 [经验准入](../dev-ascendc-3yearsz/references/evidence-learning.md) 留在交接材料；完整轮次记录留项目。
